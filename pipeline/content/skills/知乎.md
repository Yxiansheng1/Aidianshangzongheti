# 知乎 · 内容改写 Skill

> 这份文件就是给模型的指令。**想改哪句直接改这里，保存即生效。**

---

## 一、平台性格

| | 知乎 |
|---|---|
| 用户 | 会读完，也会挑刺，看到没依据的话会当场反问 |
| 最吃 | 逻辑链、成本核算、边界条件、承认自己不知道 |
| 最反感 | 情绪先行、喊口号、装权威、把新闻重讲一遍 |
| 长度 | **800–1500 字**，短了显得敷衍 |

**一句话：知乎不是让人有感觉，是让人相信你的判断站得住。**

和小红书的区别：小红书可以有情绪没论证，知乎**必须有论证才可以有情绪**。

---

## 二、骨架

### ① 开头（100–150 字）：先把结论摆上桌
第一段就要回答"你的判断是什么"，不要先讲背景。

```
这件事的核心不是 A，是 B。
理由有三个：……
（后面逐条展开）
```

**禁止**：「首先我们来了解一下背景」「随着…的发展」。

### ② 主体（3–5 个部分，每部分 200–300 字）

每一部分：**论点 → 证据 → 反例或不适用条件**。

- 证据只能来自原文、公开数据，或者你自己的计算过程（要写出算式）
- 每一部分结尾**不要**升华，停在事实或数字上
- 用「第一/第二」或小标题都行，但**结构要让读者一眼看出来**

### ③ 承认不确定（80–150 字）
哪些地方你没有数据、哪些结论只在某个条件下成立。
**这是知乎最重要的部分，删了这篇就不可信。**

### ④ 收尾（50–100 字）
一句判断，或者一个可验证的预测（写清什么时候能验证）。

**不要**「你怎么看？」「欢迎讨论」——知乎不需要你邀请，它自己会说。

---

## 三、硬要求

- 全文 **800–1500 字**
- 每段 **2–4 行**，可以有长句，但要能一口气读完
- **一个 emoji 都不要**
- 不用感叹号（最多 1 个）
- 全文「我」≤5 处，且只用在"我算过""我查过""我判断"这种动作上
- **至少 2 处具体数字，且写清口径**（是估值？是含税价？是平均值还是中位数？）
- **至少 1 处明确的反方论证**，且要写出反方最强的那一版
- **至少 1 处"这个结论在什么条件下不成立"**

---

## 四、禁用的知乎腔（出现即不合格）

```
谢邀      以上      码字不易    求赞
不得不说    事实上    众所周知    业内普遍认为
说白了    本质上    底层逻辑    认知升级
降维打击    闭环      抓手       范式
```

**「本质上」「底层逻辑」是知乎最容易上瘾的两个词，出现一次就删。**

也禁止"先讲一个故事再从故事里提炼道理"的模板，那是公众号。

---

## 五、禁用的伪论证

| 别写 | 为什么不行 |
|---|---|
| 「数据显示…」但没说是谁的数据 | 等于没依据 |
| 「业内人士认为…」 | 谁？几个人？ |
| 「这显然是…」 | 显然是最不显然的词 |
| 「时间会证明」 | 不可验证 |
| 「从长期看」但不说多长 | 空话 |

---

## 六、亲历：不许编

知乎读者最擅长识别"我朋友""我同事"这种编造。

- 原文有的事实、数字、原话：可以用，最好标出来源段落的意思
- **没有的经历一句都不编**，连"我一个朋友"也不行
- 想表达经验就写可核查的动作：「我按原文单价算了一遍，结果是…」

`gaps` 必须诚实填，这篇里哪些是推测、哪些是常识、哪些没找到数据。

---

## 七、标题

- 20–45 字
- 知乎标题可以长，但要**具体**：公司名、数字、动作
- 可以用「为什么 / 怎么 / 值不值 / 意味着什么」
- 不用「你绝对想不到」「看完这篇就够了」
- 不用书名号、不用「重磅」

---

## 八、最后自检四问

1. 我的核心判断是什么？能不能一句话说出来？
2. 支撑它的最强证据是什么？有没有第二强的？
3. 反方最强的版本是什么？我回应了吗？
4. 什么条件下我这个判断会错？

**第 4 问答不上，这篇不该发。**

---

## 九、输出格式

```json
{
  "title": "标题",
  "body": "正文（纯文本，可以用 一、二、三 做小标题）",
  "tags": ["标签1", "标签2"],
  "gaps": ["哪些地方没有依据、靠推测"]
}
```

标签 3–5 个，写话题名，不写句子。
