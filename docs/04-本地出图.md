# 本地出图（ComfyUI + Qwen-Image-Edit）

这条路不花钱，代价是时间。下面全是本机实测，不是估算——除标注「估计」的以外。

---

## 一、硬件事实

| 项 | 值 |
|---|---|
| GPU | RTX 5060 Laptop，**8 GB 显存** |
| 内存 | 63.4 GB |
| ComfyUI | `D:\AI\ComfyUI_windows_portable`（portable 版，自带 Python） |

## 二、模型三件套

| 角色 | 文件 | 大小 |
|---|---|---|
| 主模型 | `models\unet\qwen-image-edit-2511-Q8_0.gguf` | 20.27 GB |
| 文本编码器 | `models\text_encoders\qwen_2.5_vl_7b_fp8_scaled.safetensors` | 8.74 GB |
| VAE | `models\vae\qwen_image_vae.safetensors` | 0.24 GB |
| 加载器 | `custom_nodes\ComfyUI-GGUF` | — |

## 三、实测结果

| 项 | 结果 |
|---|---|
| 启动（`--lowvram --reserve-vram 1.0`） | 22 秒 |
| 单张 1024×1024 / 20 步 / cfg 2.5 | **462 秒（7.7 分钟）** |
| 显存占用 | 未 OOM，靠内存兜底 |
| 商品保真度 | 形状、瓶盖、标签完整保留 |

**这就是 8GB 显存跑 20GB 模型的代价。** 能用，但一天做 10 张就要近 80 分钟纯等待。

## 四、为什么这么慢

模型 20.27 GB，显存只有 8 GB。ComfyUI 必须不停在「显存 ↔ 内存」之间搬运权重，每一层都要搬。**瓶颈是 PCIe 带宽，不是算力。**

所以提速的核心不是调参数，是**让模型变小**。

## 五、提速路线（按性价比排序）

### 1. 换 Q4_K_M 量化 —— 最有效

Q8_0 → Q4_K_M，体积从 20.27 GB 降到约 11 GB。

- 预计提速 **2–3 倍**（估计，需实测）
- 画质损失轻微，商品图场景基本看不出
- 代价：要重新下载 11 GB

下载后改 `config.toml`：

```toml
[local]
unet = "qwen-image-edit-2511-Q4_K_M.gguf"
```

**代码不用改。** 这也是当初把模型名做成配置项的原因。

### 2. 加 Lightning LoRA —— 提速上限最高

Qwen-Image-Lightning 这类加速 LoRA，能把 20 步压到 **4–8 步**。

- 预计提速 **2.5–5 倍**（估计）
- 代价：要下 LoRA，并且要在 workflow 里插 `LoraLoaderModelOnly` 节点
- 风险：4 步的细节会掉，商品标签文字可能糊

### 3. 降分辨率

1024 → 768，像素少 44%，预计提速 **1.5 倍左右**。

```powershell
python -m pipeline gen --image xxx.png --prompt "..." --width 768 --height 768
```

代价：主图清晰度不够，淘宝现在建议 800 以上。

### 4. 减步数（不推荐）

20 → 12 步，Qwen-Image 在 12 步以下通常开始崩细节。**省不了多少时间，不值。**

### 建议顺序

先做 **1（换 Q4）**。它是唯一一个「改一行配置、画质几乎无损、提速 2–3 倍」的选项。

## 六、接线说明（改 workflow 时看这里）

本项目的 workflow 在 `pipeline/model/comfyui.py` 的 `build_qwen_edit()` 里，节点顺序：

```
UnetLoaderGGUF ──┐
                 ├→ ModelSamplingAuraFlow(shift 3.1) → KSampler
CLIPLoader ──────┘                                    ↑
 (type=qwen_image)                                    │
                                                      │
VAELoader ────────────────────────────────────────────┤
                                                      │
LoadImage ─→ TextEncodeQwenImageEditPlus(正向) ────────┤
          └→ TextEncodeQwenImageEditPlus(负向,空) ─────┘
                                                      │
                    EmptySD3LatentImage(1024×1024) ────┘
                                                      ↓
                                                  VAEDecode → SaveImage
```

关键参数：

| 参数 | 值 | 说明 |
|---|---|---|
| `cfg` | 2.5 | Qwen-Image-Edit 用低 CFG，调高会过曝变硬 |
| `shift` | 3.1 | ModelSamplingAuraFlow，Qwen 系列的标准值 |
| `sampler` | euler / simple | 官方推荐组合 |
| `denoise` | 1.0 | 图生图但走全重绘，靠 CONDITIONING 保形状 |
| `CLIPLoader type` | `qwen_image` | **写错这个会直接出乱码图** |

## 七、已知限制

1. **必须用 `--lowvram`**。不加会 OOM。
2. **不能和别的吃显存的程序同时跑**（游戏、别的 AI 工具、浏览器硬件加速）。
3. **`--lowvram` 下模型不一定常驻内存**，连续生成第二张可能仍要重新加载。要连做多张，建议一次跑一个脚本批处理，而不是反复调 CLI。
4. 生成期间别动 ComfyUI 的网页界面，容易打断队列。
