# 编排层：n8n

## 为什么是 n8n

我们的主流程是**确定性的**：出图 8 分钟 → 视频 30 分钟 → 打包 → 发布，步骤不会变。
这类事情交给工作流引擎比交给 Agent 合适——Agent 每次都要重新决策，多花钱也多一种失败方式。

选 n8n 是因为它的机制贴：**长等待（Wait 节点可以挂几十分钟）+ 重试 + 定时 + HTTP + 文件操作**，全都有。

## 流程结构

```
手动开始
  → 参数（原图路径 + 两个提示词 + 尺寸）      ← 跑之前改这里
  → POST /api/gen          提交出图，立刻返回 job.id
  → 记图任务
  → 等图20秒 ─┐
  → 查图状态 ─┘  （回环）
      ├─ status=error → 停
      ├─ status=done  → 出图结果 → POST /api/vid
      └─ 其它        → 回到「等图20秒」
  → 记视频任务 → 等视频60秒 → 查视频状态（同样的回环）
  → 完成
```

轮询用「Wait + IF 回连」实现，画布上能看到一个环。

**注意**：回环必须有退出条件。这里靠 `status` 只有 `done/error/queued/running` 四种值，
`done` 和 `error` 都会跳出。如果以后加了新状态，记得同步改 IF 条件，否则会无限循环。

## 跑之前要改什么

点开「参数」节点，改四个值：

| 字段 | 说明 |
|---|---|
| `source` | 商品原图的**绝对路径**，先传到 `input_uploads/` 或用自己的路径 |
| `imagePrompt` | 出图提示词。**只描述场景光线构图，不要描述商品外形** |
| `videoPrompt` | 视频提示词。只描述镜头运动和光线变化 |
| `size` | 1024 / 896 / 768 |

改完点右上角 **Execute workflow**。

**8GB 显存下出图约 8 分钟，视频可能半小时以上。** 跑起来就别关页面。

## 程序化调用（Webhook）

工作流已经**激活**，可以用 HTTP 直接触发，不需要人点按钮。

### 地址

```
POST http://127.0.0.1:5678/webhook/ecom-gen-video
```

### 请求体

```json
{
  "source": "D:/AIdianshangzongheti/input_uploads/xxx.jpg",
  "imagePrompt": "把商品放在浅色木纹桌面，清晨侧光，浅景深，商品保持原样不变形",
  "videoPrompt": "镜头缓慢推进，光线缓缓移动",
  "size": 1024
}
```

四个字段都有默认值，不传也行（会用工作流里写死的默认图）。

**路径用正斜杠 `/`**，反斜杠在 Windows 上容易被转义搞坏。

### 返回

```json
{"message": "Workflow was started"}
```

HTTP 200，**20 毫秒就返回**。真正的活在后台异步跑，21 分钟左右。
查进度：`http://localhost:5678` → Executions。

### 从工作台触发

「出图」页签选好图、写好提示词 → 点 **「交给 n8n 全自动（出图→视频）」**。
调的是 `/api/orchestrate`，它会转发到这个 webhook，然后立刻返回，可以关掉页面。

### 从命令行触发

```powershell
curl -X POST http://127.0.0.1:5678/webhook/ecom-gen-video `
  -H "Content-Type: application/json" `
  -d '{\"source\":\"D:/xxx/a.jpg\",\"imagePrompt\":\"...\"}'
```

### 离线备用：n8n CLI

如果 webhook 出问题，可以绕过 HTTP 直接跑：

```powershell
$env:N8N_USER_FOLDER = "D:\n8n\data"
cd D:\n8n
& ".\node_modules\.bin\n8n.cmd" execute --id K5ofUzGr89N5NCSD
```

**不会**立刻跑完就返回，会阻塞到流程结束。

## ⚠️ 一个必踩的坑

**改过工作流之后，webhook 会失效。**

用 API 或脚本 PATCH 工作流后，`active` 显示 `true`，但 webhook 返回：

```json
{"code":404,"message":"The requested webhook \"POST ecom-gen-video\" is not registered."}
```

原因是 n8n 的 webhook 注册表没有重新加载。**必须停用一次再启用**：

```powershell
POST /rest/workflows/<id>/deactivate
POST /rest/workflows/<id>/activate   {"versionId": "<当前 versionId>"}
```

注意 `/activate` **必须带 `versionId`**，只发 `{}` 不会生效（返回 200 但 active 仍是 false）。

在界面上对应的是右上角开关，关掉再打开。

## 能力清单

n8n 里所有 HTTP 节点调的接口，都在 `http://127.0.0.1:8899/api/tools` 有声明：

```powershell
curl http://127.0.0.1:8899/api/tools
```

| 能力 | 方法 | 路径 | 同步 |
|---|---|---|---|
| `orchestrate.produce` | POST | `/api/orchestrate` | 是（转发给 n8n） |
| `analyze.product` | POST | `/api/analyze` | 是 |
| `gen.image` | POST | `/api/gen` | 否（返回 job） |
| `gen.video` | POST | `/api/vid` | 否（返回 job） |
| `job.status` | GET | `/api/job?id=` | 是 |
| `file.get` | GET | `/file?path=` | 是 |
| `manifest.scan` | POST | `/api/ingest` | 是 |
| `package.listing` | POST | `/api/package` | 是 |
| `publish.plan` | POST | `/api/publish` | 是 |

**加一个能力 = 在 `server.py` 加一条 `CAPABILITIES` 记录 + 一个路由。** 不用改流程。

## 许可证的坑

n8n 用的是 **Sustainable Use License**，不是 MIT。

| 你能做 | 你不能做 |
|---|---|
| 自己用 | 把 n8n 本身当服务卖给别人 |
| 用它给客户做代运营服务 | 做一个"基于 n8n"的产品对外销售 |
| 改它、加节点 | |

**如果你最终要卖的是这个产品本身，底座要换成 MIT 的**（OpenClaw / Hermes Agent）。
如果只是自己用 + 接单做服务，n8n 完全够。

真正的复用层是 `/api/*` 这套契约：换掉 n8n，能力层一行不用改。
