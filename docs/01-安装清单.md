## 第 1 步：装 MxPage（约 2 小时，含跑通第一个商品）

### 1.1 下载

打开 <https://github.com/ziguishian/MxPage/releases/latest>

下载 `MxPage-0.3.3-windows-x64.zip`（约 341 MB），解压到任意目录，例如：

```
D:\MxPage\
```

绿色版，不用安装。双击可执行文件运行。

### 1.2 配模型

进入 MxPage 的「设置 → 模型配置」，填写：

| 字段 | 填什么 |
|---|---|
| Base URL | 供应商的接口地址（见 `docs/02-API-KEY.md`） |
| API Key | 你的 key |
| 图像模型 | **必须支持参考图输入**，这是硬条件 |

### 1.3 跑通一个真实商品

拿一个你真的想卖的品：

1. 上传商品参考图（手机拍也行，白底最佳）
2. 补充商品事实（材质、尺寸、卖点，别让它瞎编）
3. 选平台：淘宝 或 小红书
4. 生成 4 张头图 + 详情页

**验证标准**：生成出来的图，你自己愿意拿去做主图。

**不过关怎么办**：换图像模型，不要换工作流。图不行 90% 是模型选错了，不是提示词问题。

### 1.4 导出到固定目录

把作品导出到：

```
D:\MxPage\output\
```

**约定（重要）**：导出后整理成下面这样，本仓库靠这个约定识别商品。

```
D:\MxPage\output\
  渐变杯装蜡烛\
    hero-1.jpg
    hero-2.jpg
    detail-1.jpg
    title.txt      ← 可选，没有就用文件夹名
    body.txt       ← 可选，正文
    tags.txt       ← 可选，标签
```

一个商品一个文件夹，**文件夹名 = 商品名**。

## 第 2 步：装 social-auto-upload（约半天）

> ⚠️ **这一步开始有账号风险。先用小号。**

### 2.1 获取代码（放在仓库外面！）

```powershell
cd D:\
git clone https://github.com/dreammis/social-auto-upload.git
cd social-auto-upload
```

**不要克隆进 `AIdianshangzongheti`。** 许可证边界和仓库体积都会被搞乱。

### 2.2 装依赖（实测步骤）

`pyproject.toml` 里只声明了 7 个依赖，比 `requirements.txt` 那份冻结清单干净得多。用它。

```powershell
cd D:\social-auto-upload
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -U pip
.\.venv\Scripts\python.exe -m pip install -e .
Copy-Item conf.example.py conf.py
.\.venv\Scripts\python.exe -m patchright install chromium
```

注意两点：

- 它用的是 **patchright**（playwright 的隐身分支），不是 playwright。所以是 `patchright install chromium`。
- 必须 `Copy-Item conf.example.py conf.py`，否则 `sau` 一启动就报 `ModuleNotFoundError: conf`。

**验证标准**：`D:\social-auto-upload\.venv\Scripts\sau.exe --help` 能打出平台列表。

### 2.3 登录（用浏览器，只做一次）

```powershell
D:\social-auto-upload\.venv\Scripts\sau.exe xiaohongshu login --account main --headed
```

`--headed` 会弹出浏览器窗口，扫码登录你的**小号**。登录态存在 `D:\social-auto-upload\cookies\xiaohongshu_main.json`。

`--account main` 里的 `main` 是你自己起的名字，**必须和 `config.toml` 里 `[publish.accounts]` 的值一致**。

**验证标准**：

```powershell
D:\social-auto-upload\.venv\Scripts\sau.exe xiaohongshu check --account main
```

输出 `valid` 才算登录成功。

其他平台同理，把 `xiaohongshu` 换成 `zhihu` / `douyin` / `kuaishou` 等。
各平台支持的形态和硬限制见 `docs/06-平台与上货.md`。

```powershell
.\.venv\Scripts\sau.exe zhihu login --account main
.\.venv\Scripts\sau.exe zhihu check --account main
```

### 2.4 手动发一条

```powershell
cd D:\social-auto-upload
.\.venv\Scripts\sau.exe xiaohongshu upload-note `
  --account main `
  --images "D:\AIdianshangzongheti\samples\示例输出\渐变杯装蜡烛\hero-1.png" `
  --title "测试图文" --note "这条是测试" --tags "测试"
```

**验证标准**：内容真的出现在你的小号主页上，且格式正确（图不糊、标题没截断、标签生效）。

### 2.5 把路径填进本仓库

编辑 `config.toml`：

```toml
[publish]
sau_cmd = "D:\\social-auto-upload\\.venv\\Scripts\\sau.exe"
sau_cwd = "D:\\social-auto-upload"

[publish.accounts]
xiaohongshu = "main"
```

`sau_cwd` 不能省——`sau` 内部要 `import conf`，工作目录不对就启动失败。

**验证标准**：

```powershell
cd D:\AIdianshangzongheti
python -m pipeline check
```

`发布工具 sau` 那一行变成 `[ OK ]`。

以下是旧版说明，已废弃（当初按模板拼命令，实测发现参数对不上）：

<details>
<summary>（已废弃）旧的回填模板方式</summary>

第 2.4 步你实际敲了什么命令，就把它记下来，改到 `config.toml` 的 `[publish.templates]` 里：

```toml
[publish.templates]
xiaohongshu = '{sau} xiaohongshu upload --images "{images}" --title "{title}" --desc "{desc}" --tags "{tags}"'
```

**把里面的参数名换成你实际用的那个。** 本仓库不猜 CLI，只做模板替换。

</details>

## 常见卡点

| 现象 | 原因 | 处理 |
|---|---|---|
| **bat 双击一闪就关** | 文件是 LF 行尾，cmd 只认 CRLF，会把两行拼成一行报 `& was unexpected` | 仓库里的 bat 已修为 CRLF。以后别用 Git 的 `core.autocrlf=false` 覆盖 |
| MxPage 出的图商品变形 | 图像模型不支持参考图 | 换模型，别调提示词 |
| `curl` 能通但 check 报错 | base_url 少了 `/v1` | 代码会自动补，但确认没写成 `/v1/v1` |
| ingest 识别不到商品 | 图片不在子文件夹里 | 按 1.4 的结构整理 |
| sau 找不到 | 没加到 PATH | `config.toml` 里 `sau_cmd` 填绝对路径 |
| 发布失败 | 登录态过期 | 重新执行 2.3 |
| 发出去被限流 | 自动化被识别 | 降低频率、只用小号、别连发 |
