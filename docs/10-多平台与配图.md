# 多平台内容与配图

> 这份文档管两件事：**同一篇原文，各平台各写一套**；**配图必须跟文案对得上**。
> 2026-10-30 重做，之前的版本有两个硬伤，都记在最后一节。

---

## 一、平台清单

一个平台 = 一份 `pipeline/content/skills/<平台>.md`，**互不共用**。
改哪句、加哪条禁词，直接改那个 md，保存即生效，不用碰代码。

| 平台 | 字数 | 标题 | emoji | 标签 | 平台性格（一句话） | 能发什么 |
|---|---|---|---|---|---|---|
| 小红书 | 300–800 | ≤20 | 4–8 | 8 | 情绪 + 亲历 + 敢说缺点 | 图文 / 视频 |
| 抖音 | 120–300 | ≤30 | 3–6 | 5 | 第一句就是钩子，0.5 秒定生死 | 图文 / 视频 |
| 快手 | 150–300 | ≤28 | 0–3 | 4 | 这事跟你有什么关系、能省多少钱 | 图文 / 视频 |
| 知乎 | 800–1500 | ≤45 | 0 | 5 | 论证 + 边界条件，可以有情绪但必须先有论证 | 长文 / 视频 |
| 微博 | 140–280 | ≤20 | 0–2 | 2 | 一句能被截图转发的话 + 一个事实 | 只能视频 |
| B站 | 100–300 | ≤35 | 0–3 | 10 | 标题可以有梗，简介必须诚实交代 | 只能视频 |
| 视频号 | 120–250 | ≤25 | 0–2 | 3 | 「我会转给我妈看」的那种内容 | 只能视频 |
| 百家号 | 800–1200 | ≤30 | 0 | 5 | 搜索驱动，关键词覆盖优先 | 只能视频 |
| 头条 | 900–1200 | ≤30 | 0–3 | 5 | 信息密度，把一件事说清楚 | **半自动**（工具填稿，人点发布） |

**「只能视频」是 sau 的限制，不是我们偷懒。** 微博 / B站 / 视频号 / 百家号的
sau 模块只有 `upload-video`，没有图文入口。

代码里的兜底表在 `pipeline/content/rewrite.py`：

```python
TITLE_LIMITS   # 标题上限
TAG_LIMITS     # 标签个数
BODY_RANGE     # 正文字数区间
```

模型经常写超（实测小红书 955 / 上限 800、头条 1554 / 上限 1200），
所以越界时会**让它自己压一遍**（`RESIZE_PROMPT`：骨架不动、事实不动、只动表达），
压不下来才硬截，并在 `gaps` 里留一条说明。硬截会把结构切坏，所以只当兜底。

## 二、所有平台共用的底线

写在 `rewrite.py` 的 `SHARED_RULES`，**代码追加在每份 skill 后面**，
优先级高于 skill 里的风格要求。这样 9 份 skill 各写风格，底线只维护一处：

- 禁用广告法极限词（最强 / 最好 / 第一 / 唯一 / 绝对 / 100% / 史上…）
- 数字只能来自原文，一个都不许编
- **没做过的经历不许写成做过的**（这条是上一版最大的坑，见 §6）
- `gaps` 必须如实填

审核（`pipeline/review.py`）还会再过一遍：规则层查极限词和禁词，
AI 层做断言级核查。**规则层命中就是违规，不听模型解释。**

## 三、配图：主体来自文案，不来自风格

`pipeline/content/visual.py` 的逻辑：

```
plan()        从文案里挑画面，每张必须挂一句正文原话（anchor）
   ↓            anchor 必须真的出现在正文里，编的直接丢掉
render()      SDXL 文生图（20 秒/张），风格后缀只管镜头
   ↓
check()       视觉模型核对：图里到底有没有这个主体
   ↓            对不上 → revise() 重写提示词 → render_into() 重出 → 再核对
落盘          result.json 里带 checks / retried
```

三个关键约束：

1. **anchor 必须逐字出自正文**（允许 8 字窗口容错）。对不上的画面直接丢，
   宁可比要求少一张，也不配一张无关的图。
2. **风格只约束镜头**：自然光、35mm、浅景深、随手拍。
   上一版把「桌面 / 书本 / 杯子 / 植物 / 暖光」写进风格后缀，
   结果讲电路板打样的文章配出了「窗台绿植和茶杯」——风格绑架了题材。
3. **平台调性只影响光和色**（`PLATFORM_TONE`）：小红书暖、抖音对比强、
   知乎干净、快手朴素、B站偏冷、视频号明亮。

核对失败（网络/超时）**不阻塞**，只标「未核对」，不会把出好的图作废。

## 四、怎么加一个新平台

1. 新建 `pipeline/content/skills/<平台>.md`，按现有文件的结构写
   （平台性格 / 骨架 / 硬要求 / 禁用的平台腔 / 亲历规则 / 标题 / 自检 / 输出 JSON）
2. 在 `rewrite.py` 的 `TITLE_LIMITS`、`TAG_LIMITS`、`BODY_RANGE` 各加一行
3. 在 `content/publish.py` 的 `TARGETS` 和 `SAU_PLATFORM` 各加一行
   （不管能不能发都要加，发不了的写进 `NO_PUBLISH_REASON`，界面会显示原因）
4. 跑一次 `python scripts/test_platforms.py <平台>`，长度和审核都要过

**界面不用改**：写作台的下拉框读 `list_skills()`，发布按钮读 `/api/content/meta`
返回的 `publish` 表，新平台自动出现。

## 五、发布能力的真实边界

| 平台 | sau 子命令 | 额外必填 | 坑 |
|---|---|---|---|
| 小红书 | upload-note / upload-video | — | 未绑手机号不让发 |
| 抖音 | upload-note（图集）/ upload-video | — | — |
| 快手 | upload-note / upload-video | — | — |
| 知乎 | upload-article（`--content-file`）/ upload-video | `--originality` | 正文走文件，图片按 Markdown 插在原位 |
| B站 | upload-video | `--tid`（分区） | **没有 `--headed` 参数**，代码里已单独处理 |
| 视频号 | upload-video | — | — |
| 微博 | upload-video | — | 标题 ≤30 字 |
| 百家号 | upload-video | — | 只有视频 |
| 头条 | — | — | sau 没有头条模块，走「半自动填稿」（见 §5.1） |

### 5.1 头条：工具填稿，人点发布

头条号没有对个人开放的发布接口，sau 里也没有这个模块。全自动只能模拟点击
「发布」，而这是风控最敏感的动作（小红书那个号就是因此吃了两张警告）。

所以这里做成**半自动**：`pipeline/content/headline.py`

```powershell
# 必须用 sau 的 venv 跑，patchright 装在那儿
D:\social-auto-upload\.venv\Scripts\python.exe -m pipeline.content.headline login --account main
D:\social-auto-upload\.venv\Scripts\python.exe -m pipeline.content.headline fill --draft 草稿.json --account main
```

**多账号**：每个账号一份独立登录态（`output/_state/toutiao-main.json`、`toutiao-second.json`），
互不覆盖；重登前会把旧的备份成 `*.bak.json`。界面上是「账号1 / 账号2」下拉。
两个号的稿子**不要发同一篇**（头条判重复内容），要发就一稿两版。

**前置条件**：头条号必须先在后台「完善账号信息」才能发文章
（实测新号会顶着一句「请完善账号信息，解锁发布文章、视频等权益功能」，
此时编辑器能填，但点发布会卡住）。昵称也在这里设，直接用人设名。

做这三件事，然后就停：

1. 开一个**可见的** Chrome（patchright，真实会话），打开头条号图文发布页
2. 没登录就在这里等扫码，登录后自动继续，并把登录态存到 `output/_state/toutiao.json`
3. 填标题、逐段填正文（回车分段，保留空行），有图就塞进去

**不做的**：不点发布、不选封面、不选分类、不提交。这些留给人。

界面上是写作台的「**填进头条编辑器（你来点发布）**」按钮，点了会弹一个控制台窗口，
窗口里会打印每一步做了什么，同时写进 `output/_state/headline.log`。

**填完会回读核对**（2026-10-30 实测）：

```
[页面] 头条号 | https://mp.toutiao.com/profile_v4/graphic/publish
[核对] 标题回读：Mistral 开放 1 万亿参数 Le Chonk 权重
[填稿] 正文：1235 字
[核对] 正文回读：1283 字        ← 多出来的几十字是回车分段的换行
```

回读为空会明确警告「可能被遮罩挡住或没登录」，不会假装填好了。
页面若挂着「扫码登录 / 登录后」字样，日志里也会单独警告。

> 登录态存在 `output/_state/toutiao.json`（storage_state，含 `toutiao_sso_user` 等字段）。
> 如果哪天发布时提示要登录，跑一次 `headline login` 重新扫码即可。

`scripts/test_publish.py` 用 **sau 自己的 argparse** 解析一遍生成的命令，
不真的发，就能抓出参数名错、必填漏、平台没这个 flag 这三类错：

> 说明：界面上的「内容」页签是更早的队列（写作引擎是 `writer.py`，只管小红书/头条/百家号）。
> 项目 B 的多平台流程走「写作台」，两者别混用。


## 六、上一版的两个硬伤（2026-10-30 修）

### ① 配图被风格绑架

`STYLE_SUFFIX` 里写着 `cozy lived-in interior, everyday objects`，
负向词里写着 `corporate, skyscraper, office building`。
等于：**不管写什么，都得画成暖光书桌**。
讲 CircuitHub 打样那篇，出了「绿杯子 + 窗台绿植」，跟正文毫无关系。

修法：风格后缀只留镜头语言，负向词只留画质和文字；新增 anchor 机制和视觉核对。

### ② skill 逼着模型编亲历

小红书 skill 原来写着「至少 2 次亲历表达：我试过 / 我用过 / 我踩过」。
写稿的人没这些经历，模型就编——那篇真发出去的文章里
「我试过在等板那周把整张原理图重画一遍」是编的，文末 7 条 gaps 里自己也承认了。

修法：改成「可以写，但不许编」，给出三种替代（基于材料算一笔 / 指出原文的空白 /
真实比较），并把底线提到 `SHARED_RULES` 里对所有平台生效。
