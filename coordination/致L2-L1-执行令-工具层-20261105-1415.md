## 一、目标与出处

把现有 Python 能力包成"带风险等级的工具"，交给 harness 调用。
依据：`pipeline/harness/registry.py`（`ToolRegistry` / `ToolSpec` / `Risk`）与 `docs/并发分工.md`。

## 二、要做的五个工具

| 工具名 | 干什么 | 风险 | critical | 背后用什么 |
|---|---|---|---|---|
| `fetch_source` | 抓一篇原文（给链接） | read | 否 | `pipeline.article` |
| `write_draft` | 按平台 skill 写稿 | write | **是** | `pipeline.content.rewrite`（或现有 content 流程） |
| `make_image` | 出一张配图 | write | 否 | ComfyUI（`pipeline.model.comfyui`）或先留桩 |
| `fill_editor` | 填进头条编辑器 | write | **是** | subprocess 调 `pipeline.content.headline fill` |
| `publish` | 点发布 | irreversible | — | 现阶段**只留桩**，抛 `NotImplementedError` 并说明"发布仍需人工"，别真去点 |

**注意**：`fill_editor` / `publish` 走 subprocess（用 sau 的 venv python），**不要 import patchright**——harness 的 `.venv` 里没有它，也不该有。

## 四、判据（自测通过才算完）

1. `build_registry()` 返回的注册表里有 5 个工具，`describe()` 能看到风险等级
2. `fetch_source` 在 `Risk.READ` 下不用审批就能跑
3. `publish` 抛 `ApprovalRequired`（不是 `NotImplementedError` 先撞上）——顺序要对：先门禁后执行
4. `pytest tests/test_tools.py -q` 全绿；`pytest tests -q` 不许变红
5. 工具函数**必须有类型注解和一句话说明**（会成为模型看到的工具描述）
