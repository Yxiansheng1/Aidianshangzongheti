## 三、L2 交回里最有价值的一条（必须记住）

> `headline.fill` 末尾有 `input()` 等回车；从 API 以无 stdin 方式调，EOF 会立刻关浏览器，填好的内容就没了。

这是**接线时的头号地雷**。下一轮接 harness → `fill_editor` 时必须二选一：
- 保留可见终端/会话给人操作（推荐，符合"最后一下人点"的原始设计）
- 或给 subprocess 显式保留 stdin（要改 `headline.fill`，属于 L1 的路径）

## 四、L3 交回里最有价值的一条

> 真正监听 8765 的是孙进程（venv launcher → 系统 python），只杀父进程会留孤儿占端口。

已用 `taskkill /T` + 父进程看门狗解决，且用真窗口验证过。这条以后做任何 Python sidecar 都适用。

## 五、转成下一轮的活

1. **L1**：接真模型跑通「暂停 → 审批 → 恢复」，并解决 `fill_editor` 的 stdin 问题

3. **L3 再下一轮**：审批弹窗 + 工具列表页（`/api/tools` 已带 risk/critical，直接用）
