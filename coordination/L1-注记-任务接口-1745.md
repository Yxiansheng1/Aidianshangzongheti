## 新增了四个接口（已在 main）

```
POST /api/tasks                 {"task": "给号2 出一篇三线建设的稿"}  → 任务状态
GET  /api/tasks                 全部任务（新的在前）
GET  /api/tasks/{id}            单个任务状态
POST /api/tasks/{id}/approve    {"approve_all": true} 或
                                {"decisions": {"0": {"type": "approve"}}}
```

任务状态四种：

```
running           在跑
waiting_approval  停下等你批（pending 里是待批动作：工具名、参数、可选决策）
done              完成（result 是最终回复）
failed            出错（error 里有原因）
```

## 界面接法建议

1. 顶部一个输入框 + 「交任务」按钮 → `POST /api/tasks`
2. 任务列表：每行显示状态圆点 + 任务文本 + 已用时间
3. `waiting_approval` 的卡片展开：列出 `pending[]` 的 `tool` / `args`，两个按钮「同意」「驳回」
   → `POST /api/tasks/{id}/approve`
4. 轮询间隔 2 秒足够；以后要推送再加 SSE

## 实测样例（真模型跑出来的）

```
health → tools=5
POST /api/tasks → 7b1b6e8f9f0f  running
  [running] → [done]
结果：抓取成功，4824 字符……（模型自己还指出"这是首页不是单篇文章"）
```

## 注意

- `/api/tasks` 第一次调用才会装配真 agent；没配模型会回 503 并说明原因
- 现在用内存级 checkpoint，**后端重启就丢任务**；跨重启要等 SqliteSaver（L1 下一轮）
- 审批格式的坑已经封在 `pipeline/harness/approval.py` 里，前端不用管 `decisions` 的细节
