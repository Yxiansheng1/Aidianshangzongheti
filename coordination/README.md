# coordination/ — 三条线的文件信箱

> 会话之间看不到彼此的对话，只能靠这个目录传话。落盘即送达，不收平台消息。

## 角色

| 角色 | 是谁 | 干什么 | 只能改的路径 |
|---|---|---|---|
| **L1** | 主编排 | 派活、收货、合流、推送 | `pipeline/harness/**`、`pyproject.toml`、`docs/**`、`.github/**`、`coordination/**` |
| **L2** | 工具层 | 把现有能力包成工具 | `pipeline/tools/**`、`tests/test_tools.py` |
| **L3** | API + 客户端 | FastAPI 薄壳、Electron 壳 | `pipeline/api/**`、`app/**`、`tests/test_api.py` |

## 文件命名（照抄，别自创）

```
致<收件>-<发件>-<件型>-<主题>-<YYYYMMDD-HHmm>.md     定向件
<角色>-<件型>-<主题>-<HHmm>.md                        自己的产出件
例：致L2-L1-执行令-工具层-20261105-1415.md
    L2-交回-工具层-1530.md
```

## 件型（只用这几种）

| 件型 | 什么时候写 | 谁写 |
|---|---|---|
| 执行令 | 派活，含基座 sha 与判据 | L1 |
| 回执 | 收到，说明打算怎么做、预计多久 | L2 / L3 |
| 进度 | 每 30 分钟一落，或方向变了 | L2 / L3 |
| 交回 | 完工，六节：目标与出处 / 改动清单 / 红绿验证 / 测试证据 / 文档摘要 / 自检与遗留 | L2 / L3 |
| 探活 | 怀疑对端卡死 | 任意 |
| 注记 | 主动提醒，不需回复 | 任意 |

## 三条硬规矩

1. **只 `git add` 自己的路径，绝不 `git add -A`、绝不 `git push`。** 合并与推送只有 L1 做。
2. **时刻必须用 `Get-Date -Format "yyyyMMdd-HHmm"` 实取**，不许估。
3. **交回不等于收货。** L1 会自己跑一遍测试、抽样核对，绿了才算。

## L1 怎么收货

- 扫 `coordination/*-交回-*.md`，读全文（禁只看末尾）
- 在自己的树上跑 `pytest tests -q` 全量
- 抽查交回件里的关键声明（测试输出、文件清单）与磁盘实际是否一致
- 合流后开列「线名 → 最终 SHA → 来源注记」
